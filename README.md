# Твой Донер — сайт заведения уличной еды

Одностраничный сайт с каталогом, корзиной, оформлением заказов на самовывоз, Telegram-уведомлениями, отзывами с модерацией и админ-панелью.

**Стек:** Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · Motion (анимации) · Supabase (PostgreSQL, Auth, Storage) · Telegram Bot API · хостинг Vercel.

## Что умеет сайт

**Публичная часть (`/`)**
- Первый экран с анимированной шаурмой: медленный поворот, реакция на мышь, параллакс при прокрутке, ингредиенты на 3D-орбите, пар и искры.
- Популярные блюда, полное меню по категориям, окно товара с добавками.
- Корзина (сохраняется при перезагрузке), пересчёт суммы, анимация добавления.
- Оформление заказа: имя, телефон, комментарий, оплата наличными/картой в заведении, самовывоз.
- Отзывы: публикуются только после одобрения владельцем; средняя оценка — по опубликованным.
- Контакты: кликабельный телефон, маршрут в Яндекс Картах, ссылки на 2ГИС и Google.
- SEO: title/description, Open Graph, `sitemap.xml`, `robots.txt`, разметка Schema.org (Restaurant), favicon.
- Адаптивность (сначала — телефоны), поддержка `prefers-reduced-motion`.

**Админ-панель (`/admin`)** — вход по email и паролю (Supabase Auth), доступ только с ролью `admin`.
- Обзор: заказы и выручка (сегодня / месяц / всего), популярные блюда, отзывы, рейтинг.
- Заказы: список, поиск, фильтры, детали, смена статуса, история статусов, отметка оплаты, повторная отправка в Telegram. Страница обновляется сама каждые 30 секунд.
- Меню: товары, цены, описания, вес, фото, категории, добавки, «нет в наличии», скрытие, «хит».
- Отзывы: одобрить / отклонить / скрыть / удалить.
- Настройки: название, телефон, адрес, график, часы приёма заказов, включение комбо-наборов, тест Telegram.

**Как устроен заказ.** Браузер отправляет только ID товаров, добавок и количество. Сервер сам берёт цены из базы (функция `create_order`), проверяет наличие и часы работы, сохраняет заказ с уникальным номером `TD-1001`, `TD-1002`… и только потом отправляет уведомление. Если Telegram недоступен, заказ всё равно сохраняется, а в админке видна пометка и кнопка «Отправить ещё раз». Повторное нажатие кнопки «Подтвердить» не создаёт второй заказ (ключ идемпотентности).

## Запуск локально

Нужно: [Node.js 20+](https://nodejs.org) и npm.

```bash
npm install
cp .env.example .env.local   # и заполните значения
npm run dev                  # http://localhost:3000
```

Другие команды: `npm run build` (сборка), `npm start` (запуск сборки), `npm run lint` (проверка кода).

Без заполненных переменных Supabase сайт откроется, но меню будет пустым, а заказы и вход в админку работать не будут.

### Локальный Supabase (по желанию, нужен Docker)

```bash
npx supabase start     # поднимет локальную базу и применит миграции из supabase/migrations
npx supabase status    # покажет локальные URL и ключи для .env.local
```

## Настройка Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и создайте проект (регион — ближайший, например Frankfurt). Сохраните пароль базы.
2. **Создайте таблицы.** Вариант А — через терминал:
   ```bash
   npx supabase login
   npx supabase link --project-ref <ID проекта из адреса панели>
   npx supabase db push
   ```
   Вариант Б — вручную: Supabase → **SQL Editor** → выполните по очереди содержимое файлов из `supabase/migrations/` (строго в порядке номеров `…0001` → `…0004`).
3. **Ключи.** Supabase → **Project Settings → API**:
   - Project URL → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` (или `publishable`) → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` (или `secret`) → `SUPABASE_SERVICE_ROLE_KEY` — **секрет**, только в `.env.local` и Vercel.
4. **Закройте регистрацию.** Authentication → Sign In / Providers → выключите «Allow new users to sign up». Покупателям регистрация не нужна, а администраторов вы создаёте сами.
5. **Адрес сайта.** Authentication → URL Configuration → Site URL = адрес вашего сайта (после публикации).

Что создают миграции: таблицы `categories`, `products`, `product_options`, `orders`, `order_items`, `order_status_history`, `reviews`, `profiles`, `store_settings`, `rate_limits`; Row Level Security на всех таблицах; функции заказа, статистики и антиспама; хранилище фото `product-images`; данные заведения и 6 категорий (комбо выключены).

## Создание первого администратора

1. Supabase → **Authentication → Users → Add user → Create new user**: email, пароль, включите «Auto Confirm User».
2. Supabase → **SQL Editor** → выполните (подставьте email):
   ```sql
   update public.profiles set role = 'admin' where email = 'owner@example.com';
   ```
3. Откройте `/admin` и войдите. Пользователь без роли `admin` увидит «нет прав администратора».

Снять права: `update public.profiles set role = 'user' where email = '…';`

## Подключение Telegram

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя и username (должен заканчиваться на `bot`).
2. BotFather пришлёт **токен** вида `123456789:AA…` → это `TELEGRAM_BOT_TOKEN`. Никому его не показывайте.
3. Владелец открывает своего бота и нажимает **Start** (иначе бот не сможет ему писать).
4. Узнайте **chat id**: откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":123456789` → это `TELEGRAM_CHAT_ID`. (Для группы: добавьте бота в группу, напишите там сообщение; id группы начинается с `-`.)
5. Добавьте обе переменные в `.env.local` / Vercel, перезапустите сайт.
6. Админка → Настройки → «Отправить тестовое сообщение».

Пример уведомления:
```
🌯 НОВЫЙ ЗАКАЗ
Номер: TD-1048
Клиент: Александр
Телефон: +7 (999) 123-45-67
СОСТАВ:
Шаурма классическая × 2 — 540 ₽
ИТОГО: 540 ₽
Оплата: Наличными при получении
Получение: Самовывоз
Статус: Новый.
```

## Публикация на Vercel

1. Загрузите проект на GitHub (секреты в репозиторий не попадают — `.env*` в `.gitignore`).
2. [vercel.com](https://vercel.com) → **Add New → Project** → выберите репозиторий. Настройки сборки определятся автоматически (Next.js).
3. **Environment Variables** — добавьте все переменные из `.env.example` (`NEXT_PUBLIC_SITE_URL` = итоговый адрес, например `https://tvoydoner.ru`).
4. **Deploy.** После изменения переменных нужен **Redeploy**.
5. Свой домен: Project → Settings → Domains. Затем обновите `NEXT_PUBLIC_SITE_URL` и Site URL в Supabase.

## Как заполнить меню

Через админку: **/admin → Меню → «+ Добавить товар»**. Для каждого товара можно указать цену, вес, описание, фото, добавки (с ценой), «нет в наличии», «хит» (попадает в «Популярные блюда»). Флажок «Требует сверки с меню» помечает позиции, данные которых нужно перепроверить.

Изменения появляются на сайте сразу после сохранения.

Комбо-наборы: создайте товары в категории «Комбо-наборы» и включите «Показывать комбо-наборы» в Настройках.

## Как заменить логотип и картинки

- **Название/контакты/график** — Админка → Настройки (хранится в таблице `store_settings`; значения по умолчанию — в `src/config/site.ts`).
- **Логотип** — компонент `src/components/ui/Wordmark.tsx`: замените текст на `<Image src="/logo.svg" … />`, файл положите в `public/`.
- **Шаурма на первом экране** — положите PNG/WebP с прозрачным фоном в `public/images/` и укажите путь в `src/config/media.ts` (`heroImage`). Анимации сохранятся.
- **Фото заведения** — `placeImage` в `src/config/media.ts`.
- **Фото блюд** — загружаются в админке, хранятся в Supabase Storage.
- **Картинка для соцсетей** — `src/app/opengraph-image.png` (1200×630).
- **Favicon** — `src/app/icon.svg`.

## Безопасность

- Все таблицы под **Row Level Security**. Посетитель может только читать активное меню, настройки и одобренные отзывы.
- Заказы и отзывы создаются **только сервером** (через `SUPABASE_SERVICE_ROLE_KEY`), с проверкой данных, защитой от повторной отправки и ограничением частоты: 6 заказов / 10 минут и 3 отзыва / сутки с одного IP (IP хранится только в виде хэша).
- Цена из браузера не принимается — итог считает база данных.
- HTML в отзывах и комментариях вырезается, ссылки в отзывах запрещены, есть ловушка для ботов.
- Админка: проверка сессии в `proxy.ts`, проверка роли `admin` на сервере в каждой странице и действии, плюс RLS в базе.
- Секретные ключи и токен Telegram есть только в переменных окружения сервера.
- Если добавляете свои SQL-функции новой миграцией — не забудьте `revoke execute … from public, anon, authenticated`, иначе Postgres разрешит их вызов всем.

Проверено локально (Supabase в Docker): 36 проверок прав доступа (аноним и обычный пользователь не могут читать заказы, менять цены, публиковать отзывы, вызывать служебные функции, повышать себе роль, загружать файлы), расчёт суммы сервером, отсутствие дублей при двойном нажатии и при 25 одновременных заказах, сохранение заказа при недоступном Telegram, антиспам отзывов, модерация, вход в админку и запрет для не-админа.

## Расходы и риски

Честно о том, что стоит учесть владельцу:

- **Supabase Free** — бесплатно, но проекты бесплатного тарифа могут приостанавливаться при длительной неактивности; лимиты на объём базы и хранилища. Для бизнеса надёжнее платный тариф (Pro, от $25/мес). Актуальные условия — на сайте Supabase.
- **Vercel Hobby** по правилам Vercel предназначен для некоммерческого использования. Для сайта бизнеса формально нужен Pro (от $20/мес). Альтернатива — другой хостинг для Next.js.
- **Оплата зарубежных сервисов из РФ** может быть затруднена.
- **152-ФЗ.** Сайт собирает имя и телефон клиентов. Закон требует политику обработки персональных данных и хранение данных граждан РФ на серверах в России при сборе. Supabase и Vercel находятся за рубежом — проконсультируйтесь с юристом; при необходимости базу можно перенести на российский хостинг PostgreSQL.
- **Telegram API** может быть недоступен из отдельных сетей; на этот случай заказы сохраняются и видны в админке.
